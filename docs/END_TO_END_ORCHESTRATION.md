# End-to-end LedgerLens system guide

This document is a single source of truth for how the system is built, what each part does, how it scales, and where it is intentionally thin. It is written for the goal of turning LedgerLens into an agentic, chatbot-first financial-review assistant with human-in-the-loop (HITL) controls.

## 1. What the system does today

LedgerLens ingests a financial document, extracts evidence with page/cell/line provenance, normalizes financial metrics, runs deterministic accounting and risk rules, and surfaces the results in a Next.js dashboard. Every finding is tied to source text. Model/LLM output is optional and cannot override deterministic checks.

```text
Upload (REST) -> Extract -> Analyze -> Persist -> Dashboard (GraphQL + polling)
```

The review pipeline is implemented in the backend and orchestrated by `ReviewService`:

- `enqueue` creates a `Review` record.
- `process` extracts, analyzes, and decides `completed`, `needs_review`, or `failed`.
- `approve` / `reject` close the HITL gate and record `human_feedback` / `human_decision`.

## 2. Folder responsibilities

### `backend/`

Python service: FastAPI, Strawberry GraphQL, SQLAlchemy, Pydantic, typed extraction and analysis.

Key files and modules:

- `src/reviewer/api/` — REST (`rest.py`) and GraphQL (`graphql.py`) adapters. `rest.py` now exposes `/v1/reviews/{id}/approve` and `/reject` for HITL.
- `src/reviewer/application/` — `ReviewService` and ports. `service.py` is the orchestrator; `ports.py` is the repository interface.
- `src/reviewer/extraction/` — `ExtractorRegistry` and extractor implementations.
  - `extractors.py`: `PlainTextExtractor`, `CsvExtractor`, `PdfExtractor`, `DoclingExtractor`, `ImageExtractor`, `DocxExtractor`, `XlsxExtractor`.
  - `PdfExtractor` uses PyMuPDF line extraction, merges wrapped labels and number lines, and falls back to OCR for scanned pages.
  - `ImageExtractor` OCRs PNG/JPG/TIFF/BMP/GIF files using the optional `[ocr]` dependency group.
- `src/reviewer/analysis/` — `financial.py` contains `extract_metrics`, derived metrics, and numeric rules. `llm.py` is an optional evidence-gated model adapter.
- `src/reviewer/domain/` — `Review`, `Finding`, `Metric`, `Evidence`, etc. No framework imports.
- `src/reviewer/infra/` — `SqlReviewRepository`, `MemoryReviewRepository`, `ReviewDispatcher`, S3/SQS/AWS adapters for cloud.
- `main.py` — FastAPI app entry point. `lambda_api.py` / `lambda_worker.py` — AWS Lambda packaging.
- `pyproject.toml` — main dependencies and optional groups: `dev`, `docling`, `ocr`.

### `frontend/`

Next.js 16 static export, Relay, Tailwind CSS v4.

Key files:

- `app/page.tsx` — renders `ReviewDashboardShell`.
- `app/agent/page.tsx` — new `/agent` route that renders the `AgentOrchestrator` HITL UI.
- `components/review-dashboard.tsx` — list, upload, metrics, and findings.
- `components/agent-orchestrator.tsx` — interactive HITL workflow with `running`, `review`, `completed` states.
- `components/relay-provider.tsx` — Relay environment wrapper.
- `lib/relay/environment.ts` — GraphQL fetch helper.
- `app/globals.css` — design tokens and custom component styles; also imports `tailwindcss` for utility classes.

### `infra/`

Terraform infrastructure-as-code.

- `infra/terraform/aws/environments/dev/` — primary AWS deployment: VPC, S3, CloudFront, API Gateway, Lambda, SQS FIFO, Aurora Serverless v2, ECR.
- `infra/terraform/environments/dev/` — retained Google Cloud / Cloud Run baseline for role alignment.
- `scripts/` — `build-and-push-lambda.sh`, `deploy-frontend-aws.sh`, `smoke.sh`.

### `docs/`

Architecture decisions, deployment runbooks, accuracy model, and roadmap.

### `packages/graphql/`

Shared schema contract between UI and API. It is currently empty in the workspace; the source of truth is `backend/src/reviewer/api/graphql.py`.

## 4. How data flows end-to-end

### 4.1 Document upload

1. `frontend/components/review-dashboard.tsx` posts a `multipart/form-data` request to `POST /v1/reviews`.
2. `api/rest.py` validates the extension, size, and non-empty body.
3. `ReviewService.enqueue` creates a `Review` with `status = queued`.
4. In Docker Compose, `BackgroundTasks` calls `ReviewService.process` in the same process. On AWS, `ReviewDispatcher` sends a message to SQS FIFO and a worker Lambda calls `process`.

### 4.2 Extraction

`ExtractorRegistry.extract` picks the first matching extractor. Order matters:

1. `PlainTextExtractor` — `.txt`, `.md`, `.json`
2. `CsvExtractor` — `.csv`
3. `DoclingExtractor` — `.pdf` if `docling` is installed
4. `PdfExtractor` — `.pdf` with PyMuPDF + optional OCR fallback
5. `ImageExtractor` — `.png`, `.jpg`, `.jpeg`, `.tiff`, `.bmp`, `.gif` via OCR
6. `DocxExtractor` — `.docx`
7. `XlsxExtractor` — `.xlsx`

If `DoclingExtractor` fails, the registry falls back to `PdfExtractor`. If `ImageExtractor` fails because OCR is not installed, it raises `UnsupportedDocumentError` and no fallback exists for images.

`PdfExtractor`:

- Uses `page.get_text("text")` to get line-broken text.
- Merges wrapped connector lines (`Total liabilities and` + `owners' equity`).
- Merges a label line with following number-only lines (`Service revenue` + `$2,750`).
- If a page has no text, renders the page to a 2x PNG and runs `pytesseract` OCR.

`ImageExtractor`:

- Opens the image with Pillow.
- Runs `pytesseract.image_to_string`.
- Applies the same line-merging logic as `PdfExtractor`.

### 4.3 Analysis

`financial.analyze` runs:

- `extract_metrics` — per page, first number after each label.
- `add_derived_metrics` — `total_liabilities` from `total_liabilities_and_equity - equity`, `current_ratio`, `debt_to_equity`, `net_margin`, `gross_margin`.
- `run_numeric_rules` — balance-sheet reconciliation, gross-profit check, liquidity, leverage, etc.
- `extract_text_findings` — PII, going-concern language, material weakness.

The `ReviewService` then checks `requires_human_review` or `severity` and sets `needs_review` accordingly.

### 4.4 Human-in-the-loop

The `ReviewStatus` enum now includes `needs_review` and `rejected`.

- `needs_review` findings are rendered in the dashboard with `requiresHumanReview` badges.
- `/agent` shows a standalone HITL orchestration UI with `Reasoning`, `Tool Execution`, and `Human Review Gate` states.
- `POST /v1/reviews/{id}/approve` sets `status = completed`, `human_decision = approved`, `human_feedback = <text>`.
- `POST /v1/reviews/{id}/reject` sets `status = rejected`, `human_decision = rejected`, `human_feedback = <text>`.
- `GraphQL` exposes `humanFeedback` and `humanDecision` on `ReviewType`.

## 5. Non-PDF and scanned document support

The backend now supports non-PDF image uploads and OCR fallback for scanned PDFs. This is the recommended path:

- **Text PDFs / spreadsheets / text files**: use built-in extractors (no extra install).
- **Scanned PDFs**: PyMuPDF text extraction returns empty, so `PdfExtractor` renders the page and runs OCR. Install `tesseract` and the Python extras with:
  ```bash
  uv pip install -e ".[ocr]"
  # or
  pip install -e ".[ocr]"
  ```
- **Image files (PNG, JPG, etc.)**: `ImageExtractor` runs OCR. Requires the same `[ocr]` group.
- **High-fidelity tables / reading order**: install `docling` with `uv pip install -e ".[docling]"`. `DoclingExtractor` is tried before `PdfExtractor`.

### Production OCR strategy

For AWS, the Tesseract binary is not installed in the Lambda image by default. Three options, in order of operational preference:

1. **Build a Lambda layer with Tesseract + language data** and attach it to the function.
2. **Run OCR as a separate worker** (Fargate or EKS) with `Pillow` + `pytesseract` / `PaddleOCR` / `easyocr`, and consume from SQS.
3. **Use Docling** as the primary PDF extractor; it bundles OCR and layout models but requires a GPU for acceptable throughput and adds model download latency.

### Recommended: OCR worker design

```text
Upload -> S3 -> SQS "ocr" -> OCR worker (Fargate) -> SQS "review" -> Review worker
```

- Keeps the API fast.
- Scales CPU/GPU independently.
- Adds page-image provenance to evidence.
- Separates OCR failures from review failures.

## 6. Agentic chatbot workflow

The `AgentOrchestrator` component (`/agent`) is the UI for a structured agent loop:

1. **Clarify & Plan** — Reasoning accordion shows the chain-of-thought, planned tool calls, and confidence.
2. **Execute** — Tool card shows tool name, arguments, and live `loading | success | error` state.
3. **Human Review Gate** — `Awaiting Human Approval` badge, side-by-side proposed action and evidence preview, feedback textarea, `Reject & Redirect` and `Approve & Execute` buttons.
4. **Completed** — Summary with export and restart.

To wire it into the real backend:

- Use `POST /v1/reviews` to upload a document.
- Poll `GET /v1/reviews/{id}/events` or GraphQL `review(id: ...)` for status.
- When `status == "needs_review"`, render the `HumanReviewGate` with the review's `findings`, `metrics`, and `evidence`.
- On approve, call `POST /v1/reviews/{id}/approve` with `{ "feedback": "..." }`.
- On reject, call `POST /v1/reviews/{id}/reject` with `{ "feedback": "..." }`.
- Refetch the review to show the new `status`, `humanFeedback`, and `humanDecision`.

For a chatbot, wrap the `AgentOrchestrator` in a chat-message bubble. The timeline becomes the assistant's progress, and the review gate blocks the chat until the user acts.

## 7. AWS scaling and deployment path

The Terraform baseline in `infra/terraform/aws/environments/dev/` is designed for the first production pilot.

```text
CloudFront -> S3 static Next.js export
API Gateway -> FastAPI Lambda
              -> RDS Data API -> Aurora PostgreSQL Serverless v2
              -> S3 source bucket
              -> SQS FIFO -> review worker Lambda
```

### Steps to deploy

1. Install `terraform`, AWS CLI, and Docker Buildx.
2. `cd infra/terraform/aws/environments/dev`
3. `cp terraform.tfvars.example terraform.tfvars`
4. `terraform init && terraform plan -out foundation.tfplan && terraform apply foundation.tfplan`
5. `cd ../../../../../` and `./scripts/build-and-push-lambda.sh`
6. Update `terraform.tfvars` with `enable_database = true`, `deploy_compute = true`, `lambda_image_uri = ...`
7. `terraform plan -out application.tfplan && terraform apply application.tfplan`
8. `./scripts/deploy-frontend-aws.sh`
9. Run `./scripts/smoke.sh` and verify the dead-letter queue is empty.

### Scaling levers

- **Aurora**: starts at 0.5 ACU, can pause after 10 idle minutes.
- **Lambda**: memory and concurrency limits.
- **CloudFront + S3**: cache static assets; invalidate on deploy.
- **SQS FIFO**: single region; for multi-region use standard queues with idempotency keys.
- **OCR**: move to Fargate or EKS when CPU/GPU throughput matters.

### Production gates before real customers

- OIDC auth and tenant ID from verified claims.
- Presigned multipart S3 uploads for files > 6 MB.
- WAF, KMS, malware scanning, and immutable audit export.
- Terraform remote state, OIDC GitHub Actions, budgets, and CloudWatch alarms.
- Alembic migrations and PostgreSQL row-level security.
- Labeled evaluation corpus and regression harness.

## 8. Current model and data accuracy

- The deterministic financial checks are the source of truth. LLM findings are optional, capped at 85% confidence, and require human review.
- `extract_metrics` deduplicates per page and picks the first number after a label.
- Derived metrics (`total_liabilities`, `current_ratio`, `debt_to_equity`, etc.) are computed from extracted values.
- The `total_liabilities` and `equity` patterns avoid matching the `Total liabilities and owners' equity` sum line.
- `gross_profit` check uses `abs(cogs)` for parenthetical COGS values.

### End-to-end testing with non-PDFs

Test with the built-in image and OCR extractors:

```python
import io
from PIL import Image, ImageDraw
from reviewer.extraction import ExtractorRegistry
from reviewer.analysis.financial import analyze

img = Image.new("RGB", (300, 120), "white")
d = ImageDraw.Draw(img)
d.text((10, 10), "Revenue $1,000", fill="black")
d.text((10, 50), "Net income $500", fill="black")
buf = io.BytesIO()
img.save(buf, format="PNG")
doc = ExtractorRegistry().extract("statement.png", buf.getvalue())
metrics, findings = analyze(doc)
```

For scanned PDFs, create a PDF with embedded image text and verify `parser == "pymupdf"` and the OCR line blocks appear.

## 9. Known risks and next steps

- **OCR quality**: Tesseract accuracy is sensitive to DPI and image quality. For production, benchmark `pytesseract`, `PaddleOCR`, and `Docling` on a labeled corpus.
- **Multi-tenant isolation**: `tenant_id` is hardcoded to `demo` and passed from service arguments, not from a verified token.
- **Document retention**: Local SQLite keeps extracted data; AWS S3 keeps source objects. Set lifecycle policies per tenant.
- **LLM safety**: Model output is redacted and evidence-gated, but the adapter is still optional and should be evaluated for hallucination.
- **Agentic persistence**: The `AgentOrchestrator` is a UI component; the real HITL state is `Review` with `human_feedback` / `human_decision`. The next step is to embed the review gate inside the chatbot and dashboard.
